# Независимое ревью диагонального прыжка

Дата: 2026-11-13. Область: только пропуск прыжка при ↑ + → + Space, раздел 1 [плана](control-and-camera-plan.md). Реализация критиком не редактируется.

## Исходный статический диагноз

В `scripts/player.gd` нет запрета прыжка при диагональном движении. `project.godot` связывает стрелки, WASD, Space и нижнюю кнопку геймпада через общий Input Map. Причина исходного сообщения игрока статически не установлена; аппаратный ghosting не доказан.

Запрос регистрируется только в `_physics_process()` через `Input.is_action_just_pressed()`. Нужно экспериментально проверить короткое нажатие и отпускание между физическими тиками. Отдельный риск: `_jump_blocked` снимается только при наблюдении отпущенного действия в физическом тике; короткое отпускание и следующее нажатие после меню требуют проверки.

Имеющийся `tests/prototype_smoke.gd` проверяет обычный прыжок, отсутствие двойного прыжка и Continue с геймпада, но не матрицу диагоналей и короткие импульсы.

## Зафиксированные критерии

- Отключённая по умолчанию диагностика различает доставленное событие, запрос/расход буфера, опору, пол, койот, блокировку меню и запуск прыжка.
- По 30 доставленных разрешённых нажатий ↑ + → + Space и W + D + Space на безопасной середине причала, бревна и бочки дают ровно по одному прыжку. Отпускание разделяет попытки.
- Остальные диагонали, одна стрелка, геймпад, разные порядки зажатия и короткий press/release между физическими тиками сохраняют прыжок.
- Буфер перед приземлением и койот после схода работают в существующих окнах; просроченные запросы не срабатывают позднее.
- Удержание, echo и новое нажатие в воздухе не создают двойного прыжка. Одно короткое нажатие не учитывается повторно через polling.
- Подтверждение меню не запускает прыжок. После отпускания следующее новое нажатие работает, включая отпускание и нажатие между физическими тиками.
- Регрессии переноса, отрыва, падения и checkpoint проверены относящимся к изменению smoke-прогоном.

## Результат проверки патча

**Независимый software PASS в проверенной области. Ручная приёмка исходного сочетания остаётся открытой.**

Проверены текущие `scripts/player.gd`, `scripts/jump_input_debug.gd`, Input Map, HUD и тестовый сценарий. Обработчик сохраняет новое нажатие до физического тика; отпускание снимает блокировку меню сразу. Признак доставленного события подавляет повторное использование старого `just_pressed`; сброс меню очищает очередь. Постоянные буфера 0.12 с и койота 0.10 с сохранены. Физическая клавиша Z добавлена к общему действию `jump`, Space сохранён; подсказка и README обновлены. Диагностика включается отдельным флагом, содержит события запроса, блокировки, постановки/расхода/истечения буфера и запуска прыжка.

Фактически изученные артефакты:

- `artifacts/diagonal-jump/baseline/results.json` и `run.log`: 211 строк, один сбой — новое отпускание/нажатие между физическими тиками после блокировки меню. Обычные диагональные попытки в baseline уже проходили. Это не воспроизводит исходную жалобу игрока на ↑ + → + Space.
- `artifacts/diagonal-jump/after/results.json` и `run.log`: Godot 4.7.2, 306 строк, 0 ошибок. По 30 проблемных стрелочных и WASD-сочетаний на каждой из трёх опор, остальные диагонали, короткий импульс, Z, удержание/echo, запрет двойного прыжка, меню с отпусканием без повторного нажатия и с повторным нажатием, синтетический геймпад, буфер перед приземлением и его истечение.
- `artifacts/diagonal-jump/regression/prototype.log`: 0 ошибок, включая меню, перенос, падение, checkpoint и полные маршруты.
- `artifacts/diagonal-jump/regression/river.log`: 120 проверок, 0 ошибок; койот через 2/5/8 тиков на бревне и бочке, края и жизненный цикл платформ.

Блокеров программной обработки по изученному патчу и артефактам не найдено. Полный набор запущен автором; критик независимо прочитал код, критерии и реальные результаты, реализацию не редактировал. В журнале двигателя есть предупреждение о хранилище корневых сертификатов; сценарии завершены.

Синтетический ввод подтверждает программную обработку, но физическая клавиатура, сочетание ↑ + → + Space, запасная Z и реальный контроллер требуют ручной проверки на устройстве игрока. Ghosting не установлен. Просмотр GUI-кадра сам по себе не подтверждает доставку физических нажатий или удобство. Исходная жалоба полностью закрытой не объявляется.
