# Хоббит: вниз по реке

Первый прототип 3D-платформера на Godot 4.7.2: тренировочная переправа по неподвижным платформам. Blender 5.3.0 проверен, но модели пока сделаны из примитивов средствами Godot.

## Запуск

Откройте `project.godot` в Godot и нажмите F6 для текущей сцены или F5 для проекта. При первом запуске дождитесь импорта. Для игры с геймпадом окно игры должно быть в фокусе.

На этом компьютере Godot находится в папке с расширением `.exe`; настоящий исполняемый файл лежит внутри. Перемещать редактор для работы не требуется.

PowerShell, из корня репозитория:

```powershell
& 'C:\Users\PC\Downloads\Godot_v4.7.2-stable_win64.exe\Godot_v4.7.2-stable_win64.exe' --path . --editor
```

Для запуска без редактора уберите `--editor`. Blender для создания моделей: `C:\Program Files\Blender Foundation\Blender 5.3\blender.exe`; `blender-launcher.exe` — установленная программа запуска.

## Управление

| Действие | Клавиатура | Геймпад |
| --- | --- | --- |
| Движение относительно камеры | WASD | Левый стик / крестовина |
| Прыжок | Пробел | Нижняя лицевая кнопка: A / Cross |
| Вернуться на старт | R | Верхняя лицевая кнопка: Y / Triangle |
| Пауза / продолжение | Esc | Start / Options |
| Выбор в меню | Стрелки | Крестовина / левый стик |
| Подтверждение в меню | Enter / пробел | A / Cross |

Привязки находятся в Project Settings → Input Map. Мёртвая зона движения — 0.2; скорость зависит от отклонения стика. Подключение контроллера обновляет подсказки без перезапуска. Обозначения кнопок зависят от модели контроллера и его распознавания системой.

Прыгайте по светлым краям платформ до флажка. При падении в реку герой возвращается на старт. Это короткий маршрут для проверки механики: течение, контрольная точка и финальный уровень на 2–3 минуты относятся к следующим этапам.

## Проверки

Команды из корня репозитория (консольный вариант Godot):

```powershell
$godotExe = 'C:\Users\PC\Downloads\Godot_v4.7.2-stable_win64.exe\Godot_v4.7.2-stable_win64_console.exe'
& $godotExe --headless --path . --editor --import --quit
& $godotExe --headless --path . --script res://tests/prototype_smoke.gd
& $godotExe --path . --script res://tests/prototype_smoke.gd -- --capture
```

Последняя команда кратковременно запускает графику, сохраняет `artifacts/prototype.png` и завершает процесс. Сценарий проверяет настоящую сцену и физику, привязки клавиатуры, синтетические события геймпада и три прохода маршрута. Он не заменяет ручную оценку удобства управления и проверку физического контроллера.

В ограниченной среде агента перед командами задаётся `$env:APPDATA = Join-Path (Get-Location) '.godot\local-appdata'` и создаётся эта папка, чтобы Godot записывал локальные настройки внутри рабочего каталога. В обычном пользовательском терминале это не требуется.

## Файлы

- `scenes/` — главная сцена и персонаж.
- `scripts/` — движение, камера, построение тренировочного уровня и интерфейс.
- `tests/` — воспроизводимая проверка прототипа.
- `doc/initial-plan.md` — план игры; `doc/gauntlet-loop.md` — приёмка; `doc/workbench.md` — фактический прогресс.

Godot MCP и Blender MCP для запуска не нужны. Генерируемые `.godot/` и `artifacts/` не хранятся в Git.
